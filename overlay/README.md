# 接下来 5 首 · 点歌调度 + OBS 叠加层

给直播间观众看「接下来要放哪 5 首」，同时负责**点歌排队和插播**。

```
抖音弹幕 ──> songbot（识别/解析）──> queue.inbox.jsonl
                                          │
                                   本工具（排队/调度）
                                          │  嗷呜连接器（CEF 桥）
                                          ▼
                                   网易云音乐客户端
                                          │
                                   网易云播放队列（歌单）
```

- **songbot** 只负责认弹幕、写一行「谁点了什么」，不碰网易云、不需要管理员。
- **本工具** 负责排队、规则、把队头插成「下一首」、显示、以及控制面板。

## 启动

双击 **`Start.bat`**（会弹 UAC，连接器需要管理员）。

它只启动一个进程，songbot 会被它**当作子进程自动拉起来**（`config.json` 里
`songbot.auto_start = true`），所以不用再单独开那个窗口：

```
OBS 浏览器源： http://127.0.0.1:8790/
控制面板：     http://127.0.0.1:8790/admin
手机访问：     http://192.168.x.x:8790/admin?token=123456
```

启动时会**同时打开两个页面**：OBS 用的叠加层，和控制面板（带 token，不用手输）。
不想要就改 `open_browser` / `open_admin`。

关掉这个窗口时，songbot 和弹幕进程会被一起收掉（用 Windows Job Object 绑的，
就算主进程崩溃也不会留下孤儿）。

## OBS 里加

来源 → `+` → **浏览器**：

- URL：`http://127.0.0.1:8790/`
- 宽 `460`，高 `320`（5 行时）
- 背景透明，不用额外设置

## 控制面板

`http://127.0.0.1:8790/admin`

从上到下四块：

1. **规则设置**：四个数字框 + 「保存」

   | 项 | 含义 |
   | --- | --- |
   | 同人冷却（秒） | 同一个观众两次点歌至少隔多久，0 = 不限制 |
   | 每人同时最多排队（首） | 一个观众同时能排几首 |
   | 同一首歌不重复（分钟） | 同一首歌多久内不再接受（按歌名或歌曲 id 判断） |
   | 点歌过期（分钟） | 启动时丢弃多久以前的积压点歌 |

   保存后**立即生效**，并写回 `config.json`（重启也保留）。主播手动点歌不受冷却和每人上限限制。
2. **手动点歌**：三行输入
   - `歌名`（如 `18`）+ `歌手`（可选，如 `Miles Away`）——走搜索匹配；
   - 或直接粘贴**网易云歌曲链接**（`music.163.com/song?id=...`，带 `uct2=` 之类的参数也没关系）——
     **优先使用**，只取 `id`，按 id 精确入队，完全不靠搜索猜；歌名/歌手会自动查出来显示。

   点歌人默认「主播」，可以改。主播手动点不受 10 秒冷却和每人 5 首限制，但仍然查重复
   （同名或同一个歌曲 id 15 分钟内不重复）。
3. **弹幕监听（songbot）**：状态灯、最后一条点歌时间、本次累计入队、pid，
   以及 `开始监听 / 停止监听 / 重启` 和可展开的最近日志。
4. **点歌队列**：每条的状态、置顶、删除。

| 按钮 | 作用 |
| --- | --- |
| 加入队列 | 手动点歌（见上） |
| 开始 / 停止监听 | 拉起或停掉 songbot（弹幕识别），不影响已经排好的点歌 |
| 重启 | 弹幕连接抽风时一键重连 |
| 暂停接单 / 恢复接单 | 只影响"接不接受新点歌"，不影响已排好的和正在播的 |
| 跳过当前 | 跳过**正在播放的那首**（歌单曲或点歌都行）；跳的是点歌时，会直接播下一首点歌 |
| 清空队列 | 清掉所有待播点歌（已插进网易云队列的队头仍会播完，删不掉） |
| 置顶 | 把某首排到队头，立即重新插成"下一首" |
| 删除 | 只能删**非队头**的；队头撤不掉，要撤请用「跳过」 |
| 刷新状态 | 重新读一次客户端状态 |

### 手机也能控

`config.json` 里 `lan.enabled` 默认已经是 `true`，首次启动会自动生成 6 位口令，
并**自动加一条防火墙放行规则**（TCP 8790）。

手机连**同一个 Wi-Fi 或热点**，打开启动窗口里打印的地址：

```
http://192.168.x.x:8790/admin?token=123456
```

面板顶部也会显示这个地址（带口令），点开即可。口令存在浏览器里，下次不用再输。

- 连不上先确认：手机和电脑是不是同一个网络；电脑是不是换 IP 了（重开热点会变）。
- 想关掉局域网访问：`lan.enabled` 改 `false`，就只监听 `127.0.0.1`。

## 规则（都在本工具里执行）

默认值：

- 同一个人 10 秒内只能点一首
- 同一个人同时最多排 5 首
- 同一首歌 15 分钟内不重复
- 队列不设硬上限
- 启动时丢弃超过 30 分钟的记录（开播前攒的旧点歌不会一次插进来）

这些都可以在**控制面板 → 规则设置**里直接改，保存即生效并写回 `config.json`。
手动改 `config.json` 的 `rules` 段也行，重启后生效。

## 显示规则

- 只显示**待播**的 5 首，不显示正在播放的
- 点歌排前面并带点歌人；不足 5 首时用网易云歌单里"当前曲之后"的曲目补位（不显示点歌人）
- 点歌 ≥5 首时，歌单行完全不出现
- 总排队数 >5 时，标题显示「接下来 · 共 N 首排队」
- 新点歌进来时，顶部弹 3 秒「『XXX』点了《歌》」

## 播放衔接

- 队头点歌被插成网易云的「下一首」，当前曲放完自动接上
- 连续点歌之间不夹歌单曲（跳过点歌时用 `InterruptSelected` 直接播下一首点歌）
- 点歌队列空了，就回到你的歌单自然播放
- 点歌**永远不主动打断**你正在放的歌

├─ overlay.py        入口：HTTP + 调度

## 排错

| 接口 | 看什么 |
| --- | --- |
| `/api/health` | 连接器状态、事件数、队列长度、最后一次调度时间 |
| `/api/state` | 完整队列 + 当前/下一首 + 最近被丢弃的点歌及原因 |

常见情况：

- **面板显示「连接器 未运行」** → 没用管理员启动，或者网易云没开
- **歌单区显示「歌单同步中…」** → 当前播放的歌不在网易云播放列表里（比如你在放私人漫游/电台），切回歌单播放就恢复
- **点歌一直不插** → 看 `/api/state` 里的 `rejects` 和连接器状态；搜不到的歌会被跳过
- **视频里字号太小** → 改 `web/index.html` 的 `font-size`，OBS 里别用缩放硬拉

## 代理

连接器（网易云搜索）和 songbot 的弹幕子进程都会**强制绕过代理**：
启动时会清掉 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY` 并设 `NO_PROXY=*`。

原因：网易云和抖音直连都是几十毫秒，一旦继承了终端里的代理变量，
搜索会绕一圈甚至超时，点歌就被跳过、看起来"卡卡的"。

启动窗口里如果看到这行，说明检测到了并已处理：

```
[i] 检测到代理变量 HTTP_PROXY, HTTPS_PROXY，已对连接器禁用（搜索直连更快）
```

这只影响子进程，你自己终端里设的代理照旧。
